사용자가 요청한 기능
1. 업무마다 Markdown 문서를 작성하고 수정할 수 있게 한다. 잘 만들어진 오픈소스 에디터를 연동한다.
2. 현재 '업무 상세' 화면에서 기존 정보가 차지하는 영역을 최소화하고, 문서를 바로 작성/수정할 수 있는 문서 중심 화면으로 바꾼다. 노션처럼 리치 편집이 주된 경험이어야 한다.
3. Markdown 원문 텍스트를 직접 편집하는 모드도 제공한다. 단순 textarea와 미리보기만 제공하는 구현으로 끝내지 않는다.
4. 문서가 있는 업무는 '작업' 컬럼의 각 셀 오른쪽 위 모서리에 아주 작은 문서 아이콘으로 표시한다. 여기서 컬럼은 표시 이름이 바뀌어도 내부 키 title인 작업명 컬럼이다. 행 번호 칸이나 다른 속성에 표시하지 않는다.
5. 문서 아이콘을 클릭하거나 기존 업무 상세 진입 동작을 이용하면 같은 업무 문서를 열고 내용을 확인/편집할 수 있다.

화면과 편집 동작
- 상세 화면을 열면 제목과 필요한 최소 요약, 넓은 리치 문서 편집 영역이 우선 보이게 한다. 기존 속성/업무 정보는 접기나 보조 영역으로 정리하고 기존 속성 수정 및 업무 동작의 접근성을 유지한다.
- 문서가 없는 업무도 상세 화면에서 바로 첫 문서를 작성할 수 있어야 한다.
- 기본 진입 모드는 리치 보기/편집이고, 명확한 전환 동작으로 Markdown 원문을 편집한다. 편집 모드 전환, 상세 닫기/다시 열기, 새로고침으로 본문이 사라지지 않아야 한다.
- 제목/문단, 굵게·기울임, 목록·체크리스트, 인용, 링크, 코드 블록 등 실용적인 Markdown 편집을 지원한다. 표 지원과 Markdown 왕복 변환 범위를 확인하고, 원문을 리치 모드로 전환할 때 지원하지 않는 내용을 조용히 삭제하지 않도록 한다.
- 한글 IME 입력, 붙여넣기, 문서 안의 실행취소/재실행, 단축키가 정상 동작하도록 한다. 문서 입력이 뒤쪽 업무표의 단축키나 셀 편집을 작동시키지 않아야 한다.
- 문서 아이콘은 작게 표시하되 클릭 영역, 접근 가능한 이름, 키보드 진입, 툴팁을 제공한다. 제목 텍스트, 넘침 표시, 선택 테두리, 셀 편집/드래그와 충돌하지 않게 한다.
- 실질적인 문서 내용이 저장되면 아이콘을 표시하고, 본문을 비우면 제거한다. 표 새로고침과 문서 저장 직후에도 표시가 일치해야 한다.
- 원본 업무의 저장 방식은 기존 앱의 자동 저장 경험과 일관되게 설계한다. 저장 진행/성공/실패가 명확하고, 실패나 동시 수정 충돌 시 입력이 보존되어야 한다. 문서를 옮겨 열거나 닫을 때 미저장 입력을 잃지 않게 한다.
- 팀 테마 5종, 좁은 화면, 키보드 탐색 및 기존 모달/패널 규칙과 조화롭게 구현한다.

오픈소스 선택
- 공식 문서와 저장소를 확인해 유지보수 상태, 라이선스, 현재 React 19/TypeScript/Vite와의 호환, 한글 입력, 리치 편집 품질, Markdown import/export의 보존성, 접근성, 번들 크기를 비교한다.
- 필요 기능을 오픈소스 범위에서 제공하는 편집기를 선택하고 선택 이유 및 제한을 짧게 남긴다. 특정 라이브러리는 아직 확정하지 않았다.
- 패키지/잠금 파일과 프로젝트의 라이선스 고지 절차를 함께 처리한다. 에디터 자체를 새로 만드는 방식보다 검증된 편집기의 공식 확장 API를 사용한다.

데이터, 권한 및 기존 기능과의 연결
- 현재 구조는 React + TypeScript + Vite, Express, SQLite이다. 현행 저장 형식/스키마 정책에 맞춰 문서 저장 모델과 API를 구현하고 자료형 및 크기 검증을 추가한다.
- 업무 목록 API는 문서 존재 여부 등 작은 메타데이터만 가져오고, 문서 본문과 무거운 에디터 코드는 상세를 열 때 불러오도록 설계한다. 모든 업무 본문이나 에디터 인스턴스를 그리드의 각 셀에 적재하지 않는다.
- 원본 문서의 조회/수정은 해당 팀과 업무의 기존 canEdit 권한을 서버에서도 검증한다. 열람자는 읽기 전용이다. 동시 수정과 늦은 응답이 다른 문서나 새로운 입력을 덮어쓰지 않게 한다.
- 본문 렌더링에서 임의 HTML/스크립트 및 위험한 링크가 실행되지 않도록 편집기/Markdown 처리 경계를 검증한다.
- 업무 복제/행 복사·붙여넣기, 삭제·휴지통 복구, 백업 및 JSON 반출과 문서의 관계를 실제 호출 경로에서 검토하고, 문서가 유실되거나 원본과 복사본이 같은 가변 저장 대상을 공유하지 않게 한다.
- 스냅샷에는 저장 당시의 문서 내용도 독립적으로 보관한다. 이후 원본 문서를 변경·삭제해도 기존 스냅샷은 보존되어야 한다.
- 스냅샷 조회 중에는 문서도 읽기 전용이다. '스냅샷 수정' 중 문서를 수정한다면 기존 보고본 초안과 '변경 저장'/'수정 취소', 실행취소 및 revision 충돌 처리에 포함하고, 원본 업무 API로 저장하지 않는다. 문서가 없던 기존 스냅샷도 정상 조회되어야 한다.
- 기존 저장된 필터 복귀, 스냅샷 전환, 보고본의 독립 서식/업무 편집, 셀 입력 및 한글 IME를 회귀시키지 않는다.

성능 관련 인계 사항
- 직전 조사에서 빠른 스크롤 시 본문이 하얗게 되는 현상이 일반 업무와 스냅샷 모두에서 재현됐다. 이 현상은 새 스냅샷 UI 변경 전에도 존재한다.
- 기존 행/셀 메모화와 행 높이 캐시는 유지되지만, 행만 가상화하고 각 행의 화면 밖 열까지 모두 그리며 overscan이 앞뒤 12행이다. 합성 2,000행·58열, Chromium CPU 4배 감속 환경의 900px 스크롤은 약 74~86ms, 표시 열을 10개로 줄이면 약 28ms였다. 빠른 실제 휠 제스처의 빈 본문도 열 수를 줄였을 때 사라졌다. 감속하지 않은 같은 합성 환경에서는 전체 빈 본문이 재현되지 않았다.
- 이 조사에서 스크롤 구현은 변경하지 않았다. 이번 문서 기능이 표의 초기 번들이나 행 렌더링 부담을 늘리지 않도록 코드 분리, 본문 지연 조회 및 가벼운 존재 표시를 적용하고 측정하라. 전면적인 그리드 최적화는 문서 구현과 섞지 않는다.

완료 기준과 검증
- 실제 UI에서 새 문서 작성 → 리치/원문 왕복 → 저장 → 아이콘 표시 → 닫기/아이콘으로 다시 열기 → 새로고침 후 내용 유지 → 본문 비우기/아이콘 제거를 검증한다.
- 한글 IME, 여러 문서 간 전환, 저장 실패·재시도, 동시 수정, 권한, 원본/스냅샷 분리, 스냅샷 수정 저장/취소를 검증한다. 권한과 데이터 보존은 실제 API 경로를 검사한다.
- 기존 업무 상세/행 메뉴/셀 선택·편집/복사·붙여넣기/보고본 관련 회귀 검사를 실행하고 최신 UI에 맞지 않는 옛 기대값은 사용자 요구를 기준으로 정정한다.
- npm test, npm run build, 변경에 맞는 Chromium·Firefox·WebKit 브라우저 검사를 실행한다. 빌드된 dist가 브라우저 검사에 사용되므로 앱 변경 후 빌드를 먼저 한다. Playwright 실행 중 앱/테스트 소스를 편집하지 않는다.
- 실제 사용자 DB를 테스트 데이터로 쓰지 말고 임시 DB와 합성 업무를 사용한다. 문서 때문에 업무 목록 응답과 최초 표 렌더링에 본문/편집기 비용이 붙지 않는지 확인한다.
- 사용자 안내, 개발 안내 및 데이터/API 명세를 갱신하고 선택한 편집기의 근거·제약, 실제 검증 결과와 남은 문제가 있으면 이 새 Codex 세션에서 사용자에게 보고한다.

이 작업의 소유권은 이 새 세션에 있다. 최초 세션의 추가 지시나 감독 메시지를 기다리지 말고 이 브랜치에서 조사, 구현, 검증을 진행하라.

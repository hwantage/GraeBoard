| 경로 | 역할 |

| `src/App.tsx` | 팀·연도·개인 보기, 조회·저장, 편집과 실행취소 상태 |

| `shared/domain.js`, `coreProperties.js` | 날짜·주차, 필터·정렬·통계, 필수 속성과 구 설정 정규화 |
| `shared/fonts.js`, `themes.js` | 지원 글꼴·크기·폴백과 팀 테마 변수 |

| `tests/` | API·권한·동시 수정·이관·백업·브라우저 검증 |

프런트엔드는 React·TypeScript·Vite, API는 Express, 저장소는 Node 내장 SQLite를 사용합니다. 행 가상화는 `@tanstack/react-virtual`, 파일 변환은 ExcelJS를 사용합니다.

## 개발 실행

```sh
npm ci
npm run dev
```

Vite는 `5173`, API는 `4310` 포트를 사용합니다. 개발 프록시는 `/api`를 로컬 API로 전달합니다. 기본 포트를 변경할 때는 `vite.config.ts`도 함께 확인합니다. `.env`의 적용 방식은 [운영 안내](OPERATIONS.md#환경-설정)를 따릅니다.

개발 DB와 운영 DB를 분리합니다. 예시 계정과 업무는 최초 설정에서 선택하여 생성할 수 있습니다. 실제 운영 파일을 테스트 픽스처로 사용하지 않습니다.

## 주요 처리 흐름

### 조회와 개인 보기

로그인 후 `/api/bootstrap`에서 소속 팀·사용자를 읽고, 팀·연도별 업무와 보기를 조회합니다. 업무 응답은 ETag로 조건부 조회합니다. 팀·연도가 바뀌면 이전 요청 결과가 새 화면을 덮어쓰지 않도록 조회 대상을 검사합니다. 다른 사용자의 변경은 약 7초 간격으로 갱신하며 편집 중에는 반영을 보류합니다.

변경되지 않은 ETag 요청은 업무를 조회·직렬화하기 전에 304로 응답합니다. 조회 캐시의 전체 예산은 64MiB입니다. 원문과 gzip의 합이 예산보다 크면 gzip만 보관하고, 압축을 받지 않는 클라이언트의 응답 시에만 원문을 복원합니다. 압축본도 예산을 넘으면 캐시하지 않습니다. 이전 팀의 보기 저장이 뒤늦게 실패해도 현재 팀 화면에 오류를 표시하지 않습니다.

팀·연도 전환과 월·주차 기간 선택은 왼쪽 업무 열에서 시작합니다. 기간 표는 포인터 캡처로 월/주 단위의 연속 범위를 선택하고 드래그를 마칠 때 보기를 저장합니다. 기존 보기 설정 모달은 제거했으며 열 고정은 머리글 메뉴, 팀 기본 셀 높이는 기본 서식 관리에 있습니다. 기본 서식과 표는 `Toolbar`를 공유하고, 서식 선택·테두리 팝업은 모달 안에서 열리면 해당 dialog를 portal 대상으로 사용합니다. 발표 모드는 현재 보기와 위치를 유지하며 종료하면 화면 위치를 복원합니다.

### 셀 저장과 동시 수정

셀 편집을 확정하면 `/api/cells/batch`로 `operationId`, 셀별 `expectedVersion`, 값 또는 서식을 보냅니다. 서버는 인증·팀 접근·업무 편집 권한·속성 종류를 확인하고 전체 변경을 한 트랜잭션으로 저장합니다.

한 셀이라도 버전이 다르면 409로 전체 작업을 취소합니다. 같은 사용자의 동일 작업 ID 재시도는 이전 성공 결과를 재사용합니다. 저장 실패 시 입력과 요청을 유지하고, 재적용 시 최신 버전을 확인합니다. 실행취소도 같은 버전 검사와 저장 경로를 사용합니다.

### 속성과 상태 통계

작업·팀원·상태는 필수 속성입니다. 팀원과 지원자 값은 편집 권한에도 쓰이므로 종류를 바꿀 때 의미를 유지해야 합니다. 설정의 `revision`은 관리자 간 충돌을 검사합니다. 속성 종류 변경은 기존 셀을 변환하고, 변환 불가능한 값이 있으면 전체 변경을 취소합니다.

상태 통계는 실제 상태 옵션을 기준으로 현재 팀·연도의 전체 업무를 집계합니다. 필터·숨김은 통계 분모를 바꾸지 않습니다. 보관된 속성과 값은 기존 셀·보고본을 해석할 수 있도록 보존합니다.

### 이관과 삭제

XLSX는 미리보기 후 담당자·예외 확인을 거쳐 적용합니다. 파일·팀·행 범위 및 열 연결 설정·시트·모드·연도 조합으로 중복 적용을 방지합니다. 담당자가 비어 있으면 미지정으로 유지합니다. 여러 표가 섞인 원본에는 API의 `sheetOptions`로 업무 표의 범위를 지정할 수 있습니다. 보고본은 값·사용자·설정·보기의 별도 사본입니다.

업무 삭제는 휴지통 이동입니다. 팀 삭제는 시스템 관리자가 확인한 경우 모든 연도의 업무와 연관 데이터를 트랜잭션으로 영구 삭제합니다. 다른 팀·공용 계정은 보존하고, 활성 시스템 관리자의 유일한 팀 배속 제거를 막습니다.

## 확장과 변경

- 일반 폼 선택은 `Select.tsx`, 같은 값을 재선택하여 적용해야 하는 서식 선택은 `FormatSelect.tsx`를 사용합니다.
- 셀 스타일을 추가하면 화면·서버 검증·기본 서식·클립보드·XLSX 변환을 함께 확인합니다. 글꼴과 6~36pt 범위는 `shared/fonts.js`에서 정의합니다.
- 새 속성 동작은 기본값·기존 설정 정규화·셀 검증·이관·필터·보고본을 함께 검토합니다. 데이터 형식 변경 시 [호환 규칙](DATA_FORMAT.md)을 갱신합니다.
- 팀 테마는 `shared/themes.js`의 CSS 변수로 연결합니다. 사용자 지정 셀·칩 색상과 구분합니다.
- `#` 다음 여섯 자리 이슈 번호의 Redmine 링크는 현재 `shared/domain.js`의 `textLinks`에서 사내 주소를 사용합니다. 다른 설치처에 맞출 때 링크 규칙과 `tests/text-links.test.mjs`를 함께 수정합니다.
- GraeBoard는 표시 브랜드입니다. 기존 DB 경로, 세션 쿠키, 쓰기 요청 헤더, 클립보드 MIME과 JSON 포맷 식별자는 기존 값으로 호환됩니다.

## 검증

```sh
npm test
npm run build
npx playwright install chromium firefox webkit
npm run test:e2e
```

`npm test`는 임시 DB에서 API·권한·동시 수정·이관·백업/복구·이슈 링크를 검증합니다. `npm run test:e2e`는 별도 임시 서버와 DB를 만들고 Chromium·Firefox·WebKit에서 실제 UI를 조작합니다. `4311` 포트를 사용하며 실행 중에는 앱·테스트 소스를 바꾸지 않습니다. Linux 환경에서 브라우저 시스템 의존성이 없다면 `npx playwright install --with-deps chromium firefox webkit`를 사용합니다.

실패한 브라우저 검사는 `test-results/`에 스크린샷·트레이스를 남기고 HTML 보고서는 `playwright-report/`에 생성됩니다. 이 파일들은 Git에서 제외합니다. 테스트 데이터는 코드에서 생성한 가상 업무·계정이며 운영 DB를 사용하지 않습니다.

필요한 경우 다음 보조 명령을 실행합니다.

```sh
npm run performance
npm run performance:stress
npm run licenses
```

성능 명령은 임시 DB에 큰 데이터 집합을 생성하여 조회·저장·렌더링을 측정하고 `docs/validation/`에 로컬 결과를 저장합니다. 운영 환경의 용량·지연시간 보장으로 해석하지 않습니다. 라이선스 명령은 잠금 파일과 설치 패키지에서 [고지 목록](THIRD_PARTY_NOTICES.json)과 [원문](THIRD_PARTY_NOTICES.txt)을 갱신합니다.

`performance:stress`는 1천·1만·2만 업무를 별도 서버 프로세스에서 검증합니다. 53주 일정 열의 점유율은 각각 30%·30%·100%이며, 마지막 시나리오는 128만 셀입니다. 100개 가상 계정 중 30개 세션의 동시 조회·저장, 변경 없는 조회, 2천 셀 서식 변경, 동일 셀 충돌, Chromium의 검색·묶음·스크롤·편집 후 재조회를 확인합니다. 클라이언트의 동시 응답은 스트리밍으로 소비하여 테스트 도구가 대용량 JSON을 중복 보관하지 않게 합니다. 실제 사용자 데이터는 사용하지 않습니다.

특정 규모만 실행하려면 `npm run performance:stress -- 10000:30`처럼 `업무수:일정점유율`을 전달합니다. 결과는 `docs/validation/load-test-results.json`, 화면은 같은 폴더에 저장합니다. Node 22 이상과 설치된 Chromium이 필요하며, 2만 업무 시나리오는 수 GB의 메모리를 사용하므로 운영 서버와 분리해 실행합니다. 30개 HTTP 세션과 한 브라우저의 검증이며, 30개 브라우저 동시 사용이나 사내 네트워크의 지연시간을 측정하는 검사는 아닙니다.

검증 한계: 클립보드 자동 검사는 합성 이벤트와 브라우저 API 대역을 포함하므로 외부 Excel·OS 클립보드의 모든 조합을 보장하지 않습니다. 실제 원본 전체 이관, 운영 HTTPS·SSO, 장애 복구 시간과 모바일 전용 UX는 별도 인수 범위입니다.

## 저장소 범위

초기 저장소 등록 시점의 검증(2026-10-09): 빌드 성공, API·도메인·백업 검사 **43건**, Chromium·Firefox·WebKit의 **45개 흐름 × 3종 = 135건** 통과. 임시 DB를 이용한 로그인 화면·브라우저 제목·메뉴·하단의 그래보드 표기와 XLSX·CSV·JSON 파일명, 엑셀 작성자 정보도 확인했습니다.

소스, 잠금 파일, 테스트 코드, 실행 안내와 데이터 명세를 관리합니다. DB·백업·반출 파일·실제 환경 설정·로그·스크린샷·원본 시트가 참조된 초기 RFP는 Git에 포함하지 않습니다. `.env.example`에는 비밀값 없이 설정 항목만 제공합니다.
